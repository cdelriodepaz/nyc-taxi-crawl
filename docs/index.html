Overview

At pickup, predict whether each trip will crawl through traffic, so that the dispatcher can warn the passenger.

A trip crawls when its average speed is under 6 mph. We trained on May 2026, made every decision on June, and scored July once at the very end. Every number and every interactive part of this page comes from our repository: the same cleaning (src/data.py), the same features and the same fitted logistic regression (src/pipeline.py).

600,000yellow taxi trips, May to July 2026
18.5%of valid trips crawl (under 6 mph)
0.627PR AUC on July, scored once (baseline 0.327)
78% · 47%of July crawls warned · of warnings correct

01 · Frame

Turning “stuck in traffic” into a number

The data has no speed column. We build it from three columns, and label the trip 1 if it averaged under 6 mph. Try it with any trip.

Label a trip yourself

30 minduration = drop-off − pickup
4.0 mphspeed = miles ÷ hours
1is_crawl: under 6 mph

This label uses the drop-off time, which only exists once the trip has ended. It is the answer the model learns from, so the model itself may never see it.

What the model may see

A column is an input only if its value exists at pickup. Everything settled during or after the trip would leak the answer.

ColumnKnown at pickup?Why
tpep_pickup_datetimeAllowedGives the hour and the day of the week
PULocationID, DOLocationIDAllowedThe passenger says where they are going
trip_distanceAllowed, with a caveatTreated as the planned route a routing app gives at pickup. It is the distance actually driven, so a detour leaks a little
passenger_count, VendorIDAllowedTested, then dropped: they added only 0.002 PR AUC
tpep_dropoff_datetimeNeverIt builds the answer
fare_amountNeverThe meter charges for waiting, so a high fare gives the jam away
Fees, tip, total, RatecodeID, payment_typeNeverSettled at the end of the trip
request_sourceNeverUndocumented, empty in all of May and filled in about 27% of June and July
02 · Clean and split

Which trips can be labelled at all?

Some trips give a speed that means nothing. Switch each rule off to see what it protects. These are the exact rules in load_trips(), applied to all 600,000 raw trips.

570,327trips kept
18.5%of kept trips labelled as crawls

All five rules on: this is the data the model is trained and judged on.

The decision we are proudest of. Switch off “Distance above 0 miles”: the crawl rate jumps from 18.5% to 20.6%, because about 15,000 trips where the taxi never moved would be labelled as crawls. Nothing in the code warns about it.

Odd cases we kept and flagged

Problem (May)DecisionWhy
Flex fares, payment_type 0 (25% of valid trips)KeptThe dispatcher faces them in practice. They crawl less (11.5% against 20.8%) because they are longer
Negative fare or total (713)FlaggedRefunds and disputes. Time and distance still look plausible, and no amount is an input
Unknown zones 264 and 265Flagged“Unknown” is one more zone category
Non-standard fares, RatecodeID not 1FlaggedReal trips; the rate code is settled at the end, so it is never an input
passenger_count missing or 0FlaggedWould be imputed with the May median inside the pipeline; the final model does not use it
Two trips picked up in AprilDroppedThey belong to no split

The split: train on the past, judge on the future

May · 19.7%Train, 190,878 trips. All exploring happens here.
June · 19.0%Validation, 190,003 trips. Every decision is made here.
July · 16.8%Test, 189,444 trips. Scored once, at the end.

The percentage is the share of trips that crawl in each month. Crawls get rarer as the summer goes on, so precision measured on June is a little optimistic for July.

01 · Baselines and 03 · Features

Each part of the model had to earn its place on June

First, three baselines set the bar. Then feature groups were added one at a time to a logistic regression, and a group stayed only if June’s PR AUC improved. Everything that learns from data (imputing, scaling, one-hot encoding) sits inside a scikit-learn Pipeline, so it is fitted on May only.

The baseline ladder (June)

RungPrecisionRecallPR AUCLift
1. Always predict “no crawl”000.1901.00
2. Rule: pickup 10:00–18:59 in the 10 zones with most crawls in May0.4450.3490.2791.47
3. Decision tree, depth 2 (the bar to beat)0.3150.8330.3391.78

Lift = PR AUC ÷ positive rate: how many times better than guessing. Accuracy is not used: never warning would score 81%.

Feature groups, added one at a time (June PR AUC)

Zones add the most: they carry where the trip happens, which distance and time cannot. Passengers and vendor add 0.002 and were dropped.

Decision tree against logistic regression

The tree improves with depth but never reaches the logistic regression. With one column per zone, each split can only separate one zone from all the others.

The final model

ModelLogistic regression, max_iter=2000
NumbersDistance, log of distance, same-zone flag, airport flag: median imputing, then scaling
CategoriesHour, day of week, pickup zone, drop-off zone: one-hot, zones under 50 May trips grouped as “infrequent”
Fitted on190,878 May trips

04 · Evaluate on June

Who gets a warning? Choosing the threshold

The model gives each trip a probability; the dispatcher warns when it is at least the threshold. A missed crawl and a needless warning cost different amounts, so the threshold comes from the costs, not from 0.5. These curves are computed from the model’s scores on all 190,003 June trips.

Lift rises in July only because July has fewer crawls; PR AUC is the figure to compare across months. Precision falls for the same reason: with fewer crawls, a fixed threshold produces more false alarms.

Can the probabilities be trusted? (June)

Our modelPerfectly calibrated

Every group sits within about 3 points of the diagonal, slightly over-estimating in the middle.

Where it fails (June, threshold 0.30)

One threshold for every trip misses most crawls where crawls are rare: at night and on long trips. It is a Manhattan model: 88% of trips start there.

Reproduce

From a fresh clone to every number on this page

Requires Python 3.11 or newer. The data (about 17 MB) is downloaded by a script and never committed.

git clone <repository URL>
cd nyc-taxi-crawl
python -m venv .venv
.venv\Scripts\Activate.ps1        # Windows
source .venv/bin/activate         # macOS / Linux
python -m pip install -r requirements.txt
python data/get_data.py

Then open the notebooks in order, each with Restart → Run All. On a laptop the four run in about a minute and a half.
